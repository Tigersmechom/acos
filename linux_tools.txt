htop - классная штука для мониторинга процессов, нагрузки на ядра и слежка за памятью

ls (-l -список с правами, -h - человекочитаемо -a - все, учитывая скрытые)
?rwxrwx---
?:
- файл
d директория
l symlink
c character device - устройство работающее с непрерывным потоком байтов(обычно за этим стоит драйвер ядра)
b block device - обычно память (работа с блоками памяти)
p named pipe (FIFO) - канал передачи байтов между процессами (например: mkfifo mypipe
тогда появится специальный файл mypipe (это не файл, а просто имя через которое 2 процесса
могут взаимодействовать), и можно делать: терминал 1: cat mypipe; терминал 2: echo "hi" > mypipe, и в первом терминале это выведется)
s unix domain socket - локальный сокет для общения процессов на одной машине (мощнее FIFO (умеет двустороннее общение...))

man x - мануал работы программы x (для своей программы тоже можно сделать)
man: 1ая секция - стандартные команды терминала
2ая - сисколы
3яя - сишные функции

wc (-l - количество строк, -w - колво слов, -m - колво символов)

cat - что в файле находится

mkdir x - создать папку с названием x

hexdump - можно вывести файл в в виде байтов (-C побайтовое представление
и рядом буквы соответствующие этим байтам)

cd - переходит в предыдущую рабочую папку

cd .. - переход назад

touch file - создать "file"

pwd - текущий абсолютный путь

find / -iname "имя_файла" (/ - значит везде искать, iname - игнорировать регистр)

mv что куда - переместить

cp что куда - скоировать

echo x y...- вывести в терминал x y...

echo $? - код возврата последней программы

top - все процессы показывает

Команда tee читает из потока и записывает в файл (если echo > не работает под sudo): 
echo 1 | sudo tee "file.txt"

ln file another - создась hard link: копия паспорта этого файла и привязана к содержимому
ln -s: создаст symlink - привязан к имени и пути исходного файла (обычное понятие ссылки)
